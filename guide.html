گاوصندوق آفلاین برای رمزها، کلیدهای SSH، توکن‌ها و تجهیزات شبکه. این راهنما می‌گوید هر بخش کِی به کار می‌آید — نه فقط اینکه چه کاری می‌کند.

فایل‌ها کجا هستند

قبل از هر چیز این را بدان، چون همه‌ی تصمیم‌های بکاپ و انتقال به گوشی به آن وابسته است.

یک فایل داده داری، نه دو تا. رمزنگاری لایه‌ی جداگانه‌ای نیست — خودِ vault.kdbx رمزنگاری‌شده است.

چون همه‌چیز کنار هم است، کل این پوشه را روی فلش کپی کن و همان‌جا اجرا شود — اپ، گاوصندوق و بکاپ‌ها با هم. پوشه‌ی data/ در .gitignore است، پس هیچ رازی به مخزن گیت نمی‌رسد.

اگر keyfile بسازی، فایل دوم هم داری

vault.key داده‌ی تو نیست؛ کلیدی است که بدون آن گاوصندوق باز نمی‌شود. آن را جدا از گاوصندوق نگه دار — اگر کنار هم باشند، عملاً هیچ محافظت اضافه‌ای نداده‌ای.

۰۴

کار روزمره در اپ

چیزهایی که هر روز لازم می‌شوند.

کِیمی‌خواهی یک ورودی جدید بسازی

Ctrl+N یا دکمه‌ی + New entry. دسته را انتخاب کن، فیلد Name را پر کن، بعد Save.

تا Save نزنی هیچ‌چیز ذخیره نمی‌شود — ورودی‌های نیمه‌کاره در گاوصندوق باقی نمی‌مانند. بدون نام هم ذخیره نمی‌شود.

کِیمی‌خواهی رمزی را جایی بچسبانی

دکمه‌ی ⧉ کنار فیلد. بعد از ۳۰ ثانیه کلیپ‌بورد خودکار پاک می‌شود — و فقط اگر هنوز همان مقدار در آن باشد، تا چیزی که بعداً کپی کرده‌ای پاک نشود.

کِیمی‌خواهی فایل کلید SSH را ذخیره کنی

دسته را ssh_key کن، بعد Attach file… و مسیر ~/.ssh/id_ed25519 را بده. سپس Save.

سقف هر فایل ۵ مگابایت است؛ کلیدها و گواهی‌ها خیلی کوچک‌تر از این‌اند.

کِیدنبال چیزی می‌گردی

Ctrl+F. جست‌وجو در عنوان، برچسب، یادداشت و فیلدهای غیرمحرمانه انجام می‌شود.

مقادیر محرمانه عمداً جست‌وجو نمی‌شوند — وگرنه کسی با دسترسی به صفحه می‌توانست با تایپ حدس‌هایش بفهمد کدام درست است.

۰۵

کد دو مرحله‌ای

جایگزین Google Authenticator. کدها با یک کتابخانه‌ی مستقل مقایسه و تأیید شده‌اند.

وقتی سرویسی ۲FA را فعال می‌کند، کنار QR یک گزینه‌ی «enter manually» دارد که رشته‌ای شبیه JBSWY3DPEHPK3PXP نشان می‌دهد. آن را در فیلد totp_secret بگذار و Save بزن.

بلافاصله بالای فرم کارت کد زنده ظاهر می‌شود؛ هر ۳۰ ثانیه عوض می‌شود و شمارنده در ۵ ثانیه‌ی آخر قرمز می‌شود.

# از ترمینال
$ ./.venv/bin/python amvault.py totp "GitHub"
447336 (valid 26s)

فرقی نمی‌کند رشته با فاصله باشد، حروف کوچک باشد، یا کل لینک otpauth://… را کپی کنی — همه پذیرفته می‌شود.

این کار بخشی از فلسفه‌ی ۲FA را خنثی می‌کند

منطق دو عاملی این است که رمز «چیزی که می‌دانی» باشد و کد «چیزی که داری». وقتی هر دو در یک گاوصندوق‌اند، دیگر دو عامل مستقل نیستند.

سرویس‌های عادی (گیت‌هاب کاری، پنل‌ها، سرویس ابری): این‌جا بگذار، راحتی‌اش می‌ارزد. حساب‌های حیاتی (بانک، ایمیل اصلی، کیف پول رمزارز): seed را این‌جا نگذار.

کدهای بازیابی سرویس را هم حتماً جایی جدا نگه دار.

۰۶

کلید SSH موقت

کلید را برای مدت یک کار به ssh-agent می‌دهد و بعد پس می‌گیرد. کلید هرگز روی دیسک نمی‌نشیند.

کِییک دستور می‌زنی و کارت تمام است
$ amvault ssh GitHub -- git push origin main
Loaded id_ed25519 from 'GitHub' into ssh-agent.
SHA256:BGQNNTV7/gfhD8pR0sRo1xwVhbZ69HcMcUMA5tLdojI
1 existing agent key(s) left untouched.
…
Removed id_ed25519 from ssh-agent.

هرچه بعد از -- بیاید همان دستور است. پاک‌سازی حتی اگر دستور شکست بخورد یا Ctrl+C بزنی هم اجرا می‌شود.

کِیمی‌خواهی وارد سرور شوی
$ amvault ssh "Prod Server" -- ssh root@10.0.0.5
کِیچند دستور پشت هم داری
$ amvault ssh GitHub # شل باز می‌کند؛ exit که بزنی پاک می‌شود
$ amvault ssh GitHub --keep # لود بماند
$ amvault ssh GitHub --unload # … و بعد پاکش کن
$ amvault ssh-list # الان چه چیزی در agent است
کلیدهای خودت هرگز دست‌کاری نمی‌شوند

ssh-agent چند کلید را همزمان نگه می‌دارد و به‌ترتیب امتحان می‌کند. کلید گاوصندوق کنار کلید همیشگی‌ات اضافه می‌شود و با حذفش، agent دقیقاً به حالت قبل برمی‌گردد. پوشه‌ی ~/.ssh/ اصلاً لمس نمی‌شود.

کِیمی‌خواهی از داخل اپ به سرور وصل شوی

هر ورودی که فیلد host یا mgmt_ip داشته باشد، بالای فیلدهایش یک نوار اتصال می‌گیرد. یک کلیک: کلید همان ورودی در ssh-agent بار می‌شود و ترمینال با دستور ssh باز می‌شود.

آدرس، پورت، نام کاربری و کلید همه از خود ورودی خوانده می‌شوند — بدون کپی‌پیست.

از کجا می‌فهمد کدام کلید برای کدام سرور است؟

لازم نیست بفهمد: کلید به‌عنوان اتچمنت روی همان ورودی ذخیره شده که آدرس سرور در آن است. یک ورودی یعنی یک سرور، با آدرس و کاربر و کلید خودش، کنار هم.

خودِ ssh-agent هیچ نگاشتی از «کدام کلید برای کدام سرور» ندارد — همه‌ی کلیدها را به‌ترتیب پیشنهاد می‌دهد. اگر چند کلید بار شده باشد، سرور ممکن است قبل از رسیدن به کلید درست به سقف تلاش‌هایش برسد. برای همین اتصال با IdentitiesOnly فقط به کلید همان ورودی محدود می‌شود.

فقط فایل کلید را اتچ کن — بقیه‌اش خودکار است

تشخیص از روی محتوای فایل انجام می‌شود، نه نامش. پس کلید خصوصی با هر نامی (github_backup، id_rsa، …) شناخته می‌شود، و فایل عمومی حتی اگر پسوند .pub نداشته باشد کنار گذاشته می‌شود.

می‌توانی فایل عمومی و یادداشت را هم کنارش نگه داری؛ نادیده گرفته می‌شوند. فقط اگر دو کلید خصوصی در یک ورودی باشد می‌پرسد کدام را می‌خواهی — با --name مشخصش کن.

سه لایه‌ی محافظت

کلید در /dev/shm (حافظه‌ی رم) نوشته می‌شود، به ssh-add داده و بلافاصله حذف می‌شود · پاک‌سازی در بلوک finally است پس با وقفه هم اجرا می‌شود · به agent هم گفته می‌شود بعد از ۱۵ دقیقه خودش رهایش کند.

اگر کلید رمز دارد، آن را در فیلد passphrase همان ورودی بگذار تا خودکار داده شود.

اگر همزمان روی گوشی و دسکتاپ ویرایش کنی، هنگام ذخیره هشدار می‌گیری و از تو می‌پرسد کدام نسخه بماند — نسخه‌ی دیگر هم به‌صورت vault.kdbx.conflict-… بکاپ می‌شود، پس چیزی از بین نمی‌رود.

ادغام خودکار وجود ندارد. دو نسخه‌ی مستقل را نمی‌شود بدون حدس‌زدن آشتی داد، پس تصمیم با توست. عادت عملی: بگذار سینک تمام شود، بعد طرف دیگر را ویرایش کن.

keyfile روی گوشی

اگر keyfile را هم روی گوشی بگذاری، هر دو عامل روی یک دستگاه‌اند و عامل دوم بی‌معنا می‌شود. آن‌جا رمز اصلی قوی به‌همراه قفل بایومتریک خود اپ انتخاب بهتری است.

۰۸

بکاپ، بازگردانی، ریست

هر عملیات مخرب، قبل از حذف یک نسخه بایگانی می‌کند.

$ ./vault-admin.sh status # چه چیزی هست و کجا
$ ./vault-admin.sh backup # نسخه‌ی زمان‌دار رمزنگاری‌شده
$ ./vault-admin.sh list-backups
$ ./vault-admin.sh restore <file> # نسخه‌ی فعلی را اول بایگانی می‌کند
$ ./vault-admin.sh reset # از نو (باید RESET تایپ کنی)
کِیمی‌خواهی از نو شروع کنی

reset باید عبارت RESET را تایپ کنی. قبل از حذف، یک نسخه در data/backups/ بایگانی می‌شود — پس اگر پشیمان شدی و رمز را می‌دانی، برگشت‌پذیر است.

فایل‌های conflict باقی‌مانده هم پاک می‌شوند، اما keyfile هرگز حذف نمی‌شود؛ حذفش دسترسی به همه‌ی بکاپ‌های قبلی را از بین می‌برد.

بکاپ‌ها رمزنگاری‌شده‌اند

پس بگذارشان هر جا — فلش، تلگرام، هر ابری. هر بکاپ با همان رمزی باز می‌شود که گاوصندوق در لحظه‌ی بکاپ داشته است.

keyfile با این دستورات بکاپ نمی‌شود

خودت باید از آن نسخه بگیری، آن هم جایی غیر از محل گاوصندوق — وگرنه فلسفه‌اش از بین می‌رود.

۰۹

دستورات ترمینال

برای اسکریپت‌نویسی و کارهای سریع. با --vault می‌توانی مسیر دیگری بدهی.

# یک بار در ~/.zshrc بگذار تا کوتاه شود
$ alias amvault='"$HOME/path/to/.venv/bin/python" "$HOME/path/to/amvault.py"'

ساخت رمز

$ amvault gen -l 32 # رشته‌ی تصادفی ۳۲ کاراکتری
$ amvault gen -w 5 # عبارت پنج‌کلمه‌ای، برای تایپ روی گوشی

دو دستوری که باید با احتیاط استفاده شوند

dump همه‌چیز را به‌صورت متن ساده بیرون می‌دهد و عمداً پرچم بلند --i-understand-this-is-plaintext می‌خواهد. export هم کپی رمزنگاری‌نشده می‌سازد — بعد از استفاده پاکش کن.

رمز از ترمینال پرسیده می‌شود، هرگز از آرگومان — چون خط فرمان برای پروسه‌های دیگر قابل دیدن است و در تاریخچه‌ی شل می‌ماند. برای اتوماسیون AMVAULT_PASSWORD پذیرفته می‌شود.

۱۰

آنچه این اپ نمی‌تواند

محدودیت‌های واقعی. بهتر است بدانی تا اینکه فرض کنی وجود ندارند.

محدودیتمعنایش برای تو
ممیزی امنیتی نشدهفرمت KDBX و pykeepass پرکاربردند، اما کد اطرافشان بازبینی بیرونی نداشته. برای اسرار درجه‌یک، KeePassXC روی همین فایل گزینه‌ی آزموده‌تری است — چون فرمت مشترک است، می‌توانی هر دو را داشته باشی.
کلید از حافظه پاک نمی‌شودرشته‌های پایتون تغییرناپذیرند؛ قفل‌کردن ارجاع را رها می‌کند اما بازنویسی تضمین نمی‌شود.

کلید لودشده در دسترس کل نشست استتا وقتی در ssh-agent است، هر پروسه‌ای با کاربر تو می‌تواند از agent امضا بخواهد. این ذاتِ کار با agent است؛ --keep پنجره را بازتر می‌کند.
